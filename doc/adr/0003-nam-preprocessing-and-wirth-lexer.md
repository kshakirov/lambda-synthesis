# ADR 0003: Разделение лексического анализа через НАМ-препроцессинг и чистый LL(1) парсер по Вирту

## Статус
Утверждено (Approved)

## Контекст (Context)
При проектировании парсера рекурсивного спуска по Никлаусу Вирту для языка `Lambda-Core` мы столкнулись с классической проблемой лексического анализа: обработка склеенных символов (например, скобка вплотную к ключевому слову `(call`). 

Традиционный подход требует написания сложного конечного автомата (DFA) внутри лексера, который посимвольно перебирает состояния, обрабатываетLookahead и тащит за собой тяжелый рантайм-оверхед. Нам требовалось элегантное, детерминированное инженерное решение, которое позволит сделать сам токенизатор тривиальным и сохранит строгость однопроходного `LL(1)` разбора без левой рекурсии и откатов.

## Решение (Decision)
Мы приняли стратегическое решение разделить фазу лексического анализа на два изолированных этапа, применив отечественную математическую классику:

1. **Марковский препроцессинг (НАМ):** Перед токенизацией сырая строка пользователя прогоняется через систему детерминированных подстановок Нормальных Алгоритмов Маркова (НАМ). Все структурные символы-разделители принудительно изолируются пробелами с двух сторон по правилам:
   * `(` $\rightarrow$ ` ( `
   * `)` $\rightarrow$ ` ) `
   * `:` $\rightarrow$ ` : `
2. **Чистый Сплит (Clean Split):** После марковской зачистки строка гарантированно превращается в поток лексем, идеально разделенных пробелами. Это позволяет реализовать токенизатор как тривиальную функцию `split (== ' ')`, которая безошибочно вызывает конструкторы типа `Token` (такие как `OPAR`, `CALL`, `NUMBER Int`) через элементарный pattern matching строк.
3. **Парсер Вирта на чистом потоке:** Полученный плоский список `List Token` (или `List1 Token`) передается на вход парсеру Вирта, который с одним токеном заглядывания вперед детерминированно собирает «Железное Дерево» выражений.

## Последствия (Consequences)
* **Плюсы:**
  * Архитектурная изоляция: грязная работа со строками полностью инкапсулирована в НАМ-препроцессинге.
  * Токенизатор становится ультра-простым и избавляется от уязвимостей коллизий (ситуации вроде `(call` физически невозможны).
  * Код парсера Вирта остается кристально чистым, академическим и строго соответствующим `LL(1)` грамматике.
* **Минусы:**
  * Двойной проход по строке на этапе лексики (сначала НАМ-подстановки, затем сплит), что незначительно увеличивает затраты памяти в статике, но полностью окупается простотой и надежностью верификации.
