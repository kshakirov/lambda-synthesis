# ADR 0002: Спецификация целевого входного языка (Lambda-Core)

## Статус
Утверждено (Approved)

## Контекст (Context)
Для успешного наращивания «мяса» на созданный нами исполняемый костяк мета-интерпретатора требовалось чётко определить границы, синтаксис и семантическую модель входного языка, который будет обрабатывать наша система. Без формализации целевого языка дальнейшее расширение структуры выражений (`Term`) и написание полноценного тайпчекера (`check`) превратилось бы в хаотичное проектирование без конкретных инженерных ориентиров.

## Решение (Decision)
Мы утвердили архитектурный профиль входного языка под проектным названием **`Lambda-Core`** (или **`Mini-Rust`**). В основу языка заложены следующие тактико-технические характеристики:

1. **Парадигма и Вычисления:** Строгий, чисто функциональный язык, базирующийся на классическом типизированном лямбда-исчислении (STLC) с обязательным каррированием многопараметрических функций.
2. **Синтаксический облик (Грязный мир):** Язык имеет минималистичный синтаксис ML/Haskell-семейства с явным указанием типов в сигнатурах функций (например, `(fn (x : Int) => x + 1) 2`).
3. **Ресурсная безопасность (Перспектива):** За счёт использования метаязыка Idris 2 и его концепции QTT (Quantitative Type Theory), в `Lambda-Core` закладывается модель **аффинных/линейных типов (Affine/Linear Logic)**. Это позволит на уровне статики контролировать количество использований переменных (гарантируя уникальность владения ресурсами, файлов или памяти, аналогично Borrow Checker в языке Rust).
4. **Текущий базис:** Вся программа (скрипт) представляет собой единый замкнутый терм на верхнем уровне, что гарантирует пустой контекст типизации `[]` на входе в вычислитель (`eval`) и исключает свободные переменные «из ниоткуда».

## Последствия (Consequences)
* **Плюсы:**
  * Чёткий инженерный вектор: мы точно знаем правила сборки узлов `Abs` и `App` для достижения полноценной функциональной полноты.
  * Математический фундамент готов к интеграции продвинутых концепций управления памятью и ресурсами без изменения глобальной архитектуры интерпретатора.
* **Минусы:**
  * Логика каррирования требует от пользователя явного написания цепочек однопараметрических функций, что усложняет написание кода человеком на начальных этапах до внедрения синтаксического сахара в парсере.
